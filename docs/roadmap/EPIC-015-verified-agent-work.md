# EPIC-015: Проверенная работа агентов

## Цель

Закрыть **единственный непроверенный участок v1.0**: содержательную работу агентов. К концу эпика известно не «платформа двигает состояния», а «платформа производит работу» — и известно, какую именно, включая то, что получилось плохо.

Открывает веху [v1.1](../../ROADMAP.md).

## Контекст

### Что именно не проверено

С EPIC-006 и до конца v1.0 механика исполнения проверялась вживую многократно: контейнер стартует, клонирует ветку, сетевой allowlist блокирует неразрешённый хост, секреты передаются переменными окружения, артефакты собираются, Pull Request открывается и сливается. Проверены и **все отказные пути**: без `ANTHROPIC_API_KEY` каждая из четырёх ролей падает, и ни одна не сдвигает задачу и не пишет заглушку.

Не проверено ровно одно: **что происходит, когда ключ есть**. Ни один агент ни разу не обратился к провайдеру, поэтому неизвестно:

- доходит ли запрос до `api.anthropic.com` через Squid-прокси (хост в allowlist — [executor.go](../../agents/claude-code/executor.go), но живого обращения не было);
- достаточно ли промпта роли, чтобы агент сделал осмысленную работу, а не формально завершился;
- разбираются ли фактические ответы агента форматами, которые платформа ожидает (`verdict:`, `scope:`, `criterion:` — построчные форматы выбраны как раз ради устойчивости, но проверялись только на рукотворных примерах);
- сколько времени и токенов занимает реальная задача — то есть применим ли таймаут `executionTimeout` (30 мин).

Ограничение наследуется с [TASK-056](../../tasks/done/TASK-056-real-run-demo.md) и снимается появлением ключа **без изменений кода** — адаптер готов его принять.

### Что выяснилось при подготовке эпика

Ключ передаётся контейнеру как `docker run -e ANTHROPIC_API_KEY=...` ([lifecycle.go](../../agents/claude-code/container/lifecycle.go)). Проверено фактически: значение видно в `docker inspect` всё время жизни контейнера, и оно же попадает в argv процесса `docker` на хосте.

Из этих двух путей стоит закрывать только второй. `docker inspect` доступен тому, у кого есть доступ к Docker-сокету, а это уже эквивалент root на хосте — граница здесь не пересекается. А argv виден **любому** пользователю хоста через список процессов, в том числе непривилегированному: вот это настоящая граница, и закрывается она дёшево. Требование ADR-006 («секреты — короткоживущие, только переменные окружения») при этом не меняется — меняется способ доставки той же переменной.

Порядок в эпике не случаен: сначала перестать раскрывать ключ, потом просить настоящий.

## Scope

### Входит

- Устранение раскрытия ключа в argv при старте песочницы; остаточная видимость через `docker inspect` — названа явно как принятая.
- Сценарий прогона и **критерии оценки**: что считается содержательной работой, а что — формальным завершением. Записываются **до** прогона, чтобы результат не подгонялся под наблюдение.
- Живой прогон роли Developer с настоящим ключом: реальная задача, реальные коммиты, реальный Pull Request.
- Живые прогоны Reviewer, Project Manager и QA с настоящим ключом.
- Разбор результатов: что агенты сделали хорошо, что плохо, какие дефекты платформы это вскрыло. Дефекты — исправляются или фиксируются задачами.
- Закрытие эпика и вехи v1.1 с честной оценкой качества работы агентов.

### Не входит

- **Улучшение промптов ради лучшего результата** до того, как получен первый честный. Первый прогон измеряет то, что есть; правка промпта под наблюдение превратила бы проверку в подгонку.
- **Оценка моделей между собой** — эпик про то, работает ли платформа с провайдером, а не какая модель лучше.
- Ограничения, названные пределами v1.0 и не связанные с ключом: Tool Layer, несколько исполнителей на роль, устойчивый курсор журнала.
- Публикация тега `v1.0.0` — по-прежнему решение владельца проекта.

## Критерии завершения

- [ ] Ключ провайдера не попадает в argv процессов хоста; остаточная видимость задокументирована.
- [ ] Критерии оценки содержательной работы записаны **до** первого прогона.
- [ ] Роль Developer прошла вживую с настоящим ключом: агент обратился к провайдеру, произвёл коммиты, открыт Pull Request.
- [ ] Роли Reviewer, PM и QA прошли вживую с настоящим ключом; их результаты разобраны платформой в ожидаемых форматах.
- [ ] Результат оценён по записанным заранее критериям — **включая то, что получилось плохо**.
- [ ] Вскрытые дефекты исправлены или зафиксированы задачами.
- [ ] `make verify` — чисто; набор `-tags integration` — зелёный.

## Риски и зависимости

- **Ключ принадлежит владельцу проекта.** TASK-108/109 без него не выполняются: это не техническое препятствие, а граница полномочий. Задачи спроектированы так, чтобы всё, что можно сделать без ключа, было сделано до просьбы о нём.
- **Соблазн подогнать результат.** Первый живой прогон — единственная возможность увидеть непредвзятую картину; поэтому критерии оценки пишутся раньше него отдельной задачей, а правка промптов вынесена из scope.
- **Соблазн объявить успехом факт завершения.** Агент, формально завершившийся с кодом 0 и пустым результатом, — это провал, а не успех. Ровно та же логика, по которой платформа не выдумывает вердикт при отказе агента (EPIC-011).
- **Расход средств.** Реальные прогоны тратят деньги владельца. Сценарий должен быть минимальным из доказывающих утверждение, а не показательным.
- Зависит от: v1.0 (закрыта), [ADR-006](../adr/ADR-006-agent-execution-environment.md) (среда исполнения), [ADR-007](../adr/ADR-007-pm-qa-executors.md) (роли).
