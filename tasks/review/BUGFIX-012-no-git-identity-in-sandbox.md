# BUGFIX-012: в песочнице не задана git-идентичность — агент не может закоммитить работу

## Тип

fix

## Эпик

Вне эпика — исправление; обнаружено при подготовке к живому прогону [EPIC-015](../../docs/roadmap/EPIC-015-verified-agent-work.md) (TASK-108), затрагивает закрытый EPIC-006 (`agents/claude-code`).

## Цель

Роли Developer предписано «закоммить изменения по завершении работы» ([prompt.go](../../agents/claude-code/prompt.go)), но ни образ исполнения, ни скрипт клонирования не задают `user.name`/`user.email`. `git commit` внутри контейнера отказывает. Задача — обеспечить, чтобы коммит был выполним.

## Контекст

[script.go](../../agents/claude-code/container/script.go) настраивает `GIT_ASKPASS`, клонирует ветку, фиксирует базовый SHA и запускает команду — идентичность не задаётся нигде. [Dockerfile](../../docker/execution/Dockerfile) её тоже не задаёт, и переменной `EMAIL` в окружении нет.

**Подтверждено фактом** внутри собранного образа `ai-studio-os-execution` (git 2.39.5):

```text
$ git init -q . && echo hi > a.txt && git add a.txt && git commit -m "test"
Author identity unknown

*** Please tell me who you are.

Run
  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

$ git config --get user.email
[]
$ git config --get user.name
[]
```

Автоопределение по `root@<hostname>.(none)` не срабатывает: имя хоста контейнера не полное, и git отказывается вместо того, чтобы угадать.

**Что это значит для прогона.** Агент отработал бы, изменил файлы, но коммитов не произвёл. `Artifacts` корректно вернул бы пустой диапазон (BUGFIX-007 сделал это отличимым от ошибки), исполнение завершилось бы успешно — и по критериям TASK-107 это ровно исход **«формальное завершение»**: «исполнение завершилось успешно, но коммитов нет». Причём выглядел бы он как содержательное суждение о качестве модели, хотя это дефект платформы.

**Почему не поймали раньше.** Ни один тест не выполняет коммит внутри контейнера: `script_test.go` проверяет **текст** генерируемого скрипта, а живые прогоны EPIC-010…013 шли без ключа и до работы агента не доходили. Тестовый коммит из живой проверки BUGFIX-007 делался вручную из хост-оболочки, где идентичность уже настроена.

## Scope

### Входит

- `agents/claude-code/container/script.go` — задать `user.name`/`user.email` для клонированной рабочей копии внутри цепочки после успешного клона.
- Тесты: скрипт содержит настройку идентичности; она применяется **после** клона (до клона каталога ещё нет).
- **Живая проверка** внутри образа исполнения: коммит проходит, авторство соответствует заданному.
- `agents/claude-code/README.md` — авторство коммитов, которые производит агент.

### Не входит

- Отдельная идентичность на каждую роль: коммитит только Developer, остальным ролям коммитить прямо запрещено промптом.
- Подпись коммитов (GPG/SSH) — не предусмотрена ADR-008 и не требуется задачей.
- Настройка `--global` в образе: идентичность относится к рабочей копии конкретного исполнения, а не к образу.

## План реализации

1. `container/script.go` — константы идентичности и две команды `git config` (локальные, не `--global`) внутри цепочки `&&` сразу после `cd <workspaceDir>`, рядом с записью `BaseSHAFile`: при неудачном клоне ничего не выполняется.
   Значения — те, что честно описывают автора: имя, указывающее на платформу, и адрес вида `noreply`, не выдающий себя за человека. Точные значения — на утверждение вместе с планом.
2. `container/script_test.go` — тест на присутствие настройки и на её положение **после** `cd` и внутри цепочки `&&`.
3. Живая проверка внутри образа: клон → изменение → `git commit` → `git log --format='%an <%ae>'` показывает заданного автора.
4. `agents/claude-code/README.md` — раздел об авторстве произведённых коммитов.
5. `make verify`.

**Порядок с [BUGFIX-011](BUGFIX-011-claude-cli-refuses-root.md):** если тот решается сменой пользователя (Вариант A), эту настройку нужно проверить от того же пользователя — идентичность локальна для рабочей копии, так что смена пользователя её не ломает, но живую проверку следует выполнить после BUGFIX-011, а не до.

## Отчёт о выполнении

### Задача

BUGFIX-012 — в песочнице не задана git-идентичность, из-за чего роль Developer не могла закоммитить работу.

### Что сделано

- **Идентичность задаётся клонированной рабочей копии** двумя `git config` сразу после `cd`, внутри той же цепочки `&&`, что и запись `BaseSHAFile`: при неудачном клоне не выполняется ничего.
- **Значения — `AI Studio OS Agent <agent@ai-studio-os.local>`**, вынесены в константы с объяснением, почему именно такие: коммит агента не должен выглядеть человеческим, а домен намеренно не резолвится, чтобы адрес никому не доставлял почту.
- **Локально, а не `--global` в образе:** идентичность принадлежит клону конкретного Execution, а не образу, который переживает исполнения.
- **Тест проверяет размещение, а не только присутствие:** настройка обязана быть после `cd` (до клона каталога ещё нет) и внутри цепочки `&&` (иначе она выполнялась бы и при провалившемся клоне).

### Изменённые файлы

- `agents/claude-code/container/script.go` — константы `commitAuthorName`/`commitAuthorEmail`, две команды в скрипте.
- `agents/claude-code/container/script_test.go` — `TestCloneAndRunScript_ConfiguresCommitIdentity`.
- `agents/claude-code/README.md` — раздел об авторстве коммитов.

### Как проверялось

- **Регрессионный тест подтверждён как ловящий дефект:** при удалении обеих строк из скрипта (константы оставлены, чтобы падение было содержательным, а не ошибкой компиляции) тест падает с «script does not configure the commit identity». С исправлением — проходит.
- **Живая проверка «до/после» в одном контейнере** на настоящем клоне:

  | Ситуация | Результат |
  | --- | --- |
  | Коммит без идентичности (как было) | `Author identity unknown *** Please tell me who you are.` |
  | После двух `git config`, как их теперь ставит скрипт | `commit OK` |
  | `git log -1 --format='%an <%ae>'` | `AI Studio OS Agent <agent@ai-studio-os.local>` |
  | `git config --global --get user.email` | пусто — настройка не утекла в образ |

- `make verify` — чисто.

### Рекомендации

- **Инструкция промпта, не подкреплённая проверкой окружения, — это предположение.** Роли Developer с EPIC-010 предписано «закоммить изменения», и всё это время окружение не позволяло выполнить эту инструкцию. Стоит завести правило: каждая команда, которую промпт требует от агента, должна быть хотя бы однажды выполнена внутри образа в тесте или живой проверке.
- Вместе с [BUGFIX-011](BUGFIX-011-claude-cli-refuses-root.md) это два дефекта, полностью блокировавшие содержательный результат TASK-108, и оба найдены чтением кода и десятиминутной проверкой в контейнере — до траты средств владельца на прогон.
