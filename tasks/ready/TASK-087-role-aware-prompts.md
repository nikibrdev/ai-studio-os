# TASK-087: Role-aware промпты и конвенция файла вердикта

## Тип

feature

## Эпик

[EPIC-011 Роли исполнителей](../../docs/roadmap/EPIC-011-executor-roles.md)

## Цель

Сделать так, чтобы один и тот же адаптер `agents/claude-code` исполнял разные роли, различая их промптом ([ADR-007](../../docs/adr/ADR-007-pm-qa-executors.md)), и ввести способ, которым агент сообщает платформе решение, не наблюдаемое в коде (вердикт ревью).

## Контекст

Сейчас `buildPrompt` подставляет роль в текст, но блок инструкций один и заканчивается «Закоммить изменения по завершении работы» — то есть фактически промпт всегда Developer'ский. Для Reviewer такая инструкция бессмысленна: он не производит коммитов, он выносит вердикт.

**Вердикт — не наблюдаемый артефакт.** Коммиты платформа видит сама (`git log`), а «одобрено» или «нужны правки» из кода возврата вывести нельзя, не смешав отказ агента с отрицательным вердиктом. Решение архитектора ([EPIC-011](../../docs/roadmap/EPIC-011-executor-roles.md)): агент записывает вердикт в файл в рабочей копии, адаптер читает и разбирает его, а применяет — Orchestrator через Application Layer (TASK-088). Тот же приём, что `container.BaseSHAFile` (BUGFIX-007): данные от агента, решение за платформой.

Один адаптер и один Docker-образ на все роли — ADR-007 прямо это фиксирует, отдельные адаптеры или образы не вводятся.

## Scope

### Входит

- `buildPrompt` — блок инструкций выбирается по `ExecutorTask.Role`: Developer коммитит; Reviewer изучает изменения ветки относительно базовой и записывает вердикт в файл заданного формата. Общая часть (заголовок, тип, scope, критерии приёмки) остаётся одна.
- Роли PM и QA: инструкции предусмотрены, но диспетчеризации нет (см. «Не входит» эпика) — поддержка в промпте без ложного впечатления, что роль работает.
- Неизвестная роль — явная ошибка либо нейтральный блок без выдуманных инструкций (выбрать при реализации и обосновать), но **не** молчаливое использование Developer-инструкций.
- Конвенция файла вердикта: путь-константа рядом с `container.BaseSHAFile`, формат достаточно простой, чтобы агент не ошибся (одно ключевое слово плюс необязательный комментарий), разбор в адаптере с различением «файла нет» и «формат непонятен».
- Метод адаптера, отдающий разобранный вердикт вызывающему коду (не через `Artifacts` — вердикт не артефакт).
- Тесты: промпт различается по роли; Reviewer-промпт не содержит инструкции коммитить; разбор вердикта — одобрение, запрос правок, отсутствие файла, мусор в файле.

### Не входит

- Диспетчеризация роли Reviewer и применение вердикта — TASK-088.
- Изменение контракта `platform.Executor` (ADR-005): четыре возможности остаются; чтение вердикта — метод конкретного адаптера, а не пятая возможность контракта.
- Сетевой доступ песочницы к `apps/api` — перенесён в эпик PM/QA.

## Критерии приёмки

- [ ] Промпт различается по роли; Developer и Reviewer получают разные инструкции из одного адаптера и одного образа.
- [ ] Инструкция коммитить присутствует только у роли, которая должна коммитить.
- [ ] Вердикт разбирается из файла; различаются одобрение, запрос правок, отсутствие файла и нераспознанное содержимое.
- [ ] Неизвестная роль не получает Developer-инструкции молча.
- [ ] `make verify` — чисто.
