# TASK-092: Read-модель «ожидает решения человека» и операция чтения в API

## Тип

feature

## Эпик

[EPIC-012 Контрольные точки человека](../../docs/roadmap/EPIC-012-human-checkpoints.md)

## Цель

Дать способ узнать, какие задачи стоят в контрольной точке и ждут решения человека — в `internal/application` как read-модель и в `apps/api` как операция чтения.

## Контекст

Команды подтверждения уже существуют (`plan`, `complete-testing`), а способа увидеть, что именно ждёт решения, нет. Dashboard показывает задачи проекта, но не отличает ожидающие решения от остальных.

Контрольная точка — состояние, из которого платформа не выходит сама (нормативно — TASK-091), поэтому список **выводится из уже существующего состояния задачи** (Backlog — ждёт приёма DoR; Testing — ждёт приёмочного решения). Новых доменных понятий и состояний не вводится: `TaskProjection` уже несёт состояние и описательные поля.

## Scope

### Входит

- Read-модель в `internal/application` поверх `TaskProjection`: какие задачи ожидают решения человека и какого именно (приём DoR / приёмочное решение). Порядок результата детерминирован.
- `docs/api/` — спецификация операции чтения **до** реализации (Documentation First, тот же принцип, что EPIC-008).
- `apps/api` — операция чтения списка ожидающих решения.
- Тесты: задача в Backlog попадает в список как ожидающая DoR; в Testing — как ожидающая приёмочного решения; задачи в остальных состояниях **не** попадают; пустой список — не ошибка; изоляция по проекту.

### Не входит

- Новые состояния задачи или доменные агрегаты (см. риски эпика — это самый вероятный способ его испортить).
- UI — TASK-093/094.
- Новые команды подтверждения: `plan` и `complete-testing` уже есть и не меняются.
- Рекомендации агента как содержимое точки.

## Критерии приёмки

- [ ] Read-модель отдаёт задачи, ожидающие решения, с указанием какого именно; порядок детерминирован.
- [ ] Задачи в состояниях, не являющихся контрольными точками, в список не попадают — закреплено тестом.
- [ ] Спецификация операции в `docs/api/` написана до реализации хендлера.
- [ ] Операция чтения работает; ответ соответствует спецификации.
- [ ] `make verify` — чисто.
