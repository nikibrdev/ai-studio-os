# TASK-102: README корня и документы с отменёнными ссылками на версии

## Тип

docs

## Эпик

[EPIC-014 Стабилизация и релиз](../../docs/roadmap/EPIC-014-stabilization-release.md)

## Цель

Привести к фактическому состоянию первое, что видит читатель репозитория, и убрать из архитектурных документов ссылки на версии, которые теперь значат другое.

## Контекст

Обследование при открытии эпика:

- **`README.md` корня** утверждает «идёт EPIC-002.5 Engineering Platform» (закрыт давно) и приводит таблицу roadmap **отменённой** ревизии — той самой, про которую [ROADMAP.md](../../ROADMAP.md) в разделе «История ревизии» говорит, что она заменена 2026-07-20. Неверное описание на входе хуже отсутствующего: оно вызывает доверие.
- **`memory.md`** — «Реализация запланирована на v0.7 Memory», хотя EPIC-007 закрыт.
- **`tools.md`** — «Реализация запланирована на v0.8 Tool Layer»: слой действительно **не реализован** (`tools/` пуст) — это честно, но v0.8 стал Dashboard, то есть ссылка на версию неверна.

## Scope

### Входит

- `README.md` корня: что платформа делает сегодня (четыре роли автоматизированы, две контрольные точки человека, Orchestrator/API/Dashboard), актуальная таблица версий либо ссылка на `ROADMAP.md` вместо дублирования, снятие утверждения про идущий EPIC-002.5.
- `docs/architecture/memory.md` — статус реализации по факту.
- `docs/architecture/tools.md` — прямо сказать, что слой **не реализован** и каталог `tools/` пуст, без привязки к номеру версии.
- Сверка остальных документов на ссылки вида «запланировано на vX.Y», где номер уже значит другое.

### Не входит

- **`CONSTITUTION.md`** — содержит такую же устаревшую ссылку («v0.4 QA Engine»), но правится только через ADR по решению мейнтейнеров. Выносится владельцу проекта отдельно.
- Реализация Tool Layer.
- Изменение `ROADMAP.md` — он и есть источник истины по версиям.

## Критерии приёмки

- [ ] `README.md` корня описывает фактическое состояние; отменённой таблицы версий нет; утверждения про идущий EPIC-002.5 нет.
- [ ] `memory.md` не обещает реализацию, которая уже сделана.
- [ ] `tools.md` честно говорит, что слой не реализован, и не ссылается на номер версии, значащий другое.
- [ ] Прочие «запланировано на vX.Y» проверены; неверные исправлены.
- [ ] `make verify` — чисто.
