# TASK-098: Диспетчеризация PM на TaskCreated

## Тип

feature

## Эпик

[EPIC-013 Роли PM и QA](../../docs/roadmap/EPIC-013-pm-qa-roles.md)

## Цель

На событие `TaskCreated` Orchestrator запускает агента роли Project Manager, получает предложение Definition of Ready и применяет его через Application Layer. Задача **остаётся в Backlog** — принять DoR может только человек.

## Контекст

Механизм построен в EPIC-010/011: цикл опроса, выбор исполнителя по роли, слежение, приём результата файлом. Эта задача добавляет третью роль в существующий механизм.

**Контрольная точка сохраняется структурно:** агент не имеет доступа к `apps/api` (решение эпика), а Orchestrator вызывает только use-case уточнения (TASK-096) — не `PlanTask`. Ни один путь исполнения не переводит задачу в Ready.

**Ветка не нужна.** PM ничего не коммитит, поэтому создавать ветку и открывать Pull Request не требуется. Клонировать рабочую копию всё же нужно: чтобы предложить осмысленный scope, агенту полезно видеть код проекта.

## Scope

### Входит

- Бутстрап PM-исполнителя — тем же `EnsureExecutor`, что Developer и Reviewer.
- Обработка `TaskCreated`: представление задачи, своя запись PM-исполнителя, репозиторий, `ExecutorTask` с ролью `project-manager`, `Accept`, слежение до терминального состояния.
- При успехе — чтение предложения DoR и применение через use-case уточнения; задача остаётся в Backlog.
- **Ничего не выдумывается при отказе:** неудача агента, таймаут, отсутствующее или нераспознанное предложение оставляют задачу как есть, без уточнения. Пустой scope или выдуманные критерии хуже отсутствия: человек принял бы DoR, глядя на них.
- `Finish` — всегда, как для остальных ролей.
- Тесты: успешный путь (уточнение применено, задача **в Backlog**, `PlanTask` не вызван); каждый отказной путь (задача не изменена, `Finish` вызван); событие не `TaskCreated` → диспетчеризации нет.

### Не входит

- Диспетчеризация QA — TASK-099.
- Автоматический переход Backlog → Ready — прямо запрещён ADR-007.
- Создание ветки и Pull Request для PM — не требуется.

## Критерии приёмки

- [ ] PM-исполнитель регистрируется и активируется идемпотентно.
- [ ] На `TaskCreated` запускается агент роли `project-manager`, предложение применяется через Application Layer.
- [ ] Задача **остаётся в Backlog** после работы PM; `PlanTask` не вызывается ни на одном пути — закреплено тестом.
- [ ] Отказ, таймаут или нераспознанное предложение оставляют задачу без изменений; `Finish` вызван.
- [ ] `make verify` — чисто.
