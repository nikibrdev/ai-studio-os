# TASK-108: Живой прогон роли Developer с настоящим ключом

## Тип

test

## Эпик

[EPIC-015 Проверенная работа агентов](../../docs/roadmap/EPIC-015-verified-agent-work.md)

## Цель

Впервые провести роль Developer через реальное обращение к AI-провайдеру: агент получает задачу, пишет код, коммитит, платформа открывает Pull Request. Оценить результат по критериям, записанным заранее.

## Контекст

Ограничение, наследуемое с [TASK-056](../../tasks/done/TASK-056-real-run-demo.md): ни один агент ни разу не обратился к провайдеру. Механика вокруг этого обращения проверена вживую многократно — клон, allowlist, сбор артефактов, Pull Request, слияние; неизвестно только, что происходит между запуском агента и появлением коммитов.

Зависимости, снятые заранее: `api.anthropic.com` в сетевом allowlist ([executor.go](../../agents/claude-code/executor.go)); ключ доставляется без раскрытия в argv (TASK-106); сценарий и критерии оценки записаны (TASK-107).

**Ключ принадлежит владельцу проекта** — это граница полномочий, а не техническое препятствие. Задача начинается с запроса ключа и не выполняется без него.

## Scope

### Входит

- Прогон сценария из TASK-107 на настоящей инфраструктуре: PostgreSQL, Docker, репозиторий-песочница, действительные `GITHUB_TOKEN` и `ANTHROPIC_API_KEY`.
- Фиксация всего, что названо в TASK-107: журналы платформы и агента, состояние задачи, артефакты, время, расход.
- Применение критериев оценки **как записаны**, без смягчения формулировок под результат.
- Проверка предположений, которые до сих пор не на чем было проверить: доходит ли запрос через Squid-прокси, укладывается ли работа в `executionTimeout` (30 мин), разбираются ли фактические ответы агента ожидаемыми форматами.
- Дефекты, вскрытые прогоном, — исправляются или фиксируются отдельными задачами.

### Не входит

- Роли Reviewer, PM, QA — TASK-109.
- Правка промпта под результат первого прогона: наблюдение первично, улучшение — предмет отдельного решения после разбора.
- Повторные прогоны ради лучшей картины.

## Критерии приёмки

- [ ] Прогон выполнен с действительным ключом; факт обращения к провайдеру подтверждён, а не предположен.
- [ ] Агент произвёл коммиты; платформа собрала их как артефакты и открыла Pull Request.
- [ ] Результат оценён по критериям TASK-107, **включая то, что получилось плохо**.
- [ ] Зафиксировано фактическое время исполнения и его отношение к `executionTimeout`.
- [ ] Вскрытые дефекты исправлены или заведены задачами.
- [ ] Отчёт содержит то, что не получилось, наравне с тем, что получилось.
- [ ] `make verify` — чисто.
