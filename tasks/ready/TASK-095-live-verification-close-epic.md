# TASK-095: Живая проверка контрольных точек, закрытие EPIC-012

## Тип

test

## Эпик

[EPIC-012 Контрольные точки человека](../../docs/roadmap/EPIC-012-human-checkpoints.md)

## Цель

Подтвердить вживую на реальной инфраструктуре: задачи в контрольных точках видны, оба решения принимаются из интерфейса и меняют состояние задачи в базе. Закрыть эпик.

## Контекст

Урок EPIC-010/011: сквозная живая проверка нашла шесть дефектов (BUGFIX-004…008), невидимых для тестов, потому что каждая сторона шва тестировалась своими данными. Здесь появляются два новых шва — read-модель между проекцией и API, и **запись из браузера** в API, которой в проекте не было ни разу. Проверка обязательна до объявления эпика готовым.

**Проверяемо целиком, без ключа AI-провайдера:** контрольные точки — это состояния задачи, а не работа агента. Задачу можно привести в Backlog и в Testing существующими средствами, поэтому оба решения проверяются полностью — в отличие от EPIC-010/011, где содержательная часть упиралась в отсутствие `ANTHROPIC_API_KEY`.

## Scope

### Входит

- Прогон на реальном PostgreSQL и реальном `apps/api` + `apps/dashboard`: задача в Backlog видна как ожидающая приёма DoR; приём из UI переводит её в Ready.
- Задача, доведённая до Testing, видна как ожидающая приёмочного решения; решение из UI приводит к слиянию и Done (в репозитории-песочнице), либо возврат на доработку переводит в In Progress.
- Проверка **отказного** пути вживую: запрос при недоступном или отвечающем ошибкой API — интерфейс сообщает об ошибке и не показывает устаревшее состояние как актуальное.
- Сверка состояний **в БД через `psql`** и во внешнем репозитории через `gh api`, а не по логам приложения.
- Полный набор `-tags integration` на живой инфраструктуре (урок TASK-090: так нашёлся BUGFIX-008, не связанный с эпиком).
- Обновление критериев эпика (честно, с частичными отметками при необходимости), ROADMAP, PROJECT_MANIFEST, PROJECT_HEALTH, CHANGELOG.

### Не входит

- Открытие следующего эпика (диспетчеризация PM/QA и решение о доступе песочницы к `apps/api`) — отдельная задача после закрытия.
