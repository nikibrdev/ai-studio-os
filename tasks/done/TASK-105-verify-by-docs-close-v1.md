## Тип

## Эпик

[EPIC-014 Стабилизация и релиз](../../docs/roadmap/EPIC-014-stabilization-release.md)

## Цель

Проверить документацию единственным способом, которым её можно проверить: поднять платформу с нуля, следуя **только** написанному, и убедиться, что инструкций достаточно. Закрыть эпик и веху v1.0.

## Контекст

Все живые проверки прошлых эпиков делались с уже накопленным знанием: какие переменные окружения нужны, в каком порядке запускать, что должно быть собрано. Читатель этого знания не имеет — у него есть только README.

Опыт эпиков: каждая живая проверка находила то, чего не видели тесты (восемь дефектов за четыре эпика). Здесь проверяется не код, а **достаточность инструкций** — и найденное чинится в документации, а не обходится знанием, которого у читателя нет.

## Scope

### Входит

- Поднять платформу с нуля по README корня и README модулей: зависимости, PostgreSQL, образ песочницы, `apps/api`, `apps/orchestrator`, `apps/dashboard`.
- Фиксировать **каждый** момент, где пришлось воспользоваться знанием не из документации (переменная окружения, порядок запуска, предварительная сборка) — это и есть дефекты документации.
- Исправить найденное в документации; повторить проверку, если правки существенны.
- Обновление критериев эпика, ROADMAP (v1.0 — завершено), PROJECT_MANIFEST, PROJECT_HEALTH.
- Итог по вехе v1.0: что достигнуто и что осознанно осталось за её пределами.

### Не входит

- **Публикация тега `v1.0.0`** — решение владельца проекта (см. TASK-104).
- Исправление кода: если инструкция не работает из-за кода, а не из-за текста, — зафиксировать как отдельную задачу.
- Открытые вопросы предыдущих эпиков.

| `go test -tags=integration` на настоящих PostgreSQL и Qdrant | 18 пакетов зелёные |

**Пять мест, где пришлось знать сверх написанного** — то есть пять дефектов документации:

1. **От README корня нет пути к работающей системе.** Раздел запуска отсутствовал вовсе, `docker-compose.yml` не упоминался ни в README, ни в `CONTRIBUTING.md` (там только окружение разработки). Команды запуска существовали, но лежали в README модулей, на которые корневой README не ссылался — читатель узнаёт о них, только если догадается туда заглянуть.
2. **Документированная команда запуска `apps/orchestrator` не работает.** Приведённый в README снippet содержит только `DATABASE_URL`; процесс завершается с кодом 1 и сообщением `GITHUB_TOKEN is not set — a repository provider is required to create task branches`. В списке переменных `GITHUB_TOKEN` обязательным помечен не был — при том что соседний `ANTHROPIC_API_KEY` явно описан как допускающий пустое значение, то есть различие документ проводил, но не в ту сторону.
3. **Интеграционные тесты нельзя запустить по документации, а неверная попытка выглядит успешной.** Переменные называются `TEST_DATABASE_URL`/`TEST_QDRANT_URL` и упомянуты только в CI-конфигурации и в тексте `t.Skip`. С «очевидными» `DATABASE_URL`/`QDRANT_URL` весь набор печатает `ok` по каждому пакету, пропустив **все** тесты: 18 зелёных строк, ноль выполненных проверок. Это худший из пяти пробелов — остальные видны отказом, этот маскируется успехом.
4. **`apps/api/README.md` обещал 17 операций** — их 20 (не хватало `GET /decisions` и других, добавленных после EPIC-008).
5. **`docs/development/testing.md` устарел целиком**: запрещал создание тестов «на этапе v0.1 Foundation», называл Redis интеграционной зависимостью (не используется), фреймворк frontend — «не выбран» (Vitest выбран в EPIC-009), и держал открытыми вопросы, решённые эпиками назад.
